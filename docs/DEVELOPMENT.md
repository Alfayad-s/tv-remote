## Mock vs real TV

`TV_ADAPTER=mock` (default) is a switch:

- `127.0.0.1` / `localhost` / the mock device → `MockTVAdapter` (no PIN)
- A LAN IP from discovery or **Manual IP** → `AndroidTVAdapter` (pairing on TCP 6467)

`TV_ADAPTER=androidtv` always uses the real protocol, including for a typed LAN address.

Pairing certificates are generated by `@kud/androidtv-remote` and stored under `CREDENTIALS_DIR` as `0o600` JSON. The PWA only sends `SUBMIT_PIN`. Never log the PIN or PEM material.

## Testing discovery and pairing

1. Start `npm run dev`.
2. Confirm **Available TVs** lists the mock iFFALCON (`127.0.0.1`).
3. If your physical TV is on and advertising Remote Service, it should appear with its LAN IP after the scan (~3s).
4. Tap the mock device, then **Connect TV**, then **Send HOME** (no PIN).
5. Select the physical TV or type its IP under **Manual IP**, then **Connect TV**.
6. When the TV shows a pairing code, enter it in the PWA. A later connect to the same host should skip the PIN.
7. After **TV: Connected**, tap **Send HOME** and confirm the iFFALCON returns to the home screen.
8. Server debug logs should mention `Sent remote command` with `HOME`. They must not contain the PIN or PEM text.

That path is:

```text
PWA → DISCOVER_TVS → Node.js mDNS (_androidtvremote2._tcp) → TV_LIST
PWA → CONNECT_TV 127.0.0.1 → MockTVAdapter
PWA → CONNECT_TV <LAN IP> → AndroidTVAdapter → TLS 6467 PIN → TLS 6466 keys
```

## Phone testing on LAN

1. Find the computer IP, e.g. `192.168.1.20`.
2. Keep `HOST=0.0.0.0` so the service accepts LAN clients.
3. Open `http://192.168.1.20:5173` on the phone.
4. The page stays on port 5173 and Vite proxies `/ws` to the Node service on `8787`.
5. Allow Node through the OS firewall for ports `5173` and `8787` if needed.

Do not expose these ports on the public internet.

## Logging

Development:

```env
LOG_LEVEL=debug
```

Production:

```env
LOG_LEVEL=info
```

Never log pairing PINs or PEM material. The logger redacts known sensitive keys, but do not pass those values into log context in the first place.

## Adding a command

1. Add it to `REMOTE_COMMANDS` in `packages/shared/src/commands.ts`.
2. Extend validation tests.
3. Map it in the Android TV command layer (Phase 7+), only if the protocol actually supports it.
4. Add a UI control only after the mapping exists.

Do not fake unsupported TV functionality.
